# Presenter Run of Show — 30 min AWS Session

**Title:** Beyond AI Coding: Building Software with AI-DLC
**Core message:** Don't start from a prompt; start from an approved plan.

| Minute | Segment | Lead | Key point |
|---|---|---|---|
| 00–03 | Opening | Presenter | AI can code, but can a team deliver traceably? |
| 03–07 | AI Assisted vs AI-DLC | Presenter | Methodology / lifecycle / decisions |
| 07–11 | Inception → Construction | Presenter | Show authentic approved artifacts and handoff |
| 11–13 | Demo framing | Both | Today's scope is a CPU health classification unit, not full monitoring product |
| 13–24 | Live Construction | Engineer + presenter narration | Clone, select intent, resume, implement, test, verify |
| 24–28 | AWS positioning | Presenter | AWS Labs Workflows + Kiro; AWS infrastructure optional, not prerequisite |
| 28–30 | Closing | Presenter | From developer workflow to enterprise adoption |

## Suggested presenter lines
- Opening: "AI writing code is only part of software delivery. The harder problem is knowing what to build, why, and how we verify it."
- Before demo: "Our BA and architect have already reviewed the requirements and decisions. The engineer picks up the same workflow from Construction."
- During tests: "This is the difference: we validate business thresholds, not just code syntax."
- Closing: "Start with one workflow and one team. Scale collaboration and governance when the business case is proven."

## AWS claims discipline
- AWS Labs AI-DLC supports multiple harnesses; Kiro is our chosen demo harness, not a mandatory requirement of the method.
- This demo uses local synthetic data, not CloudWatch metrics.
- Do not suggest today's build is AWS Collaborative AI-DLC Platform or Bedrock AgentCore unless actually used.
